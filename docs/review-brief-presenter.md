## 맡기는 일

발표자가 되어 자료를 처음부터 끝까지 읽고, 아래를 정리해 달라. **자료를 직접 고치지 말고 고칠 목록으로** 돌려 달라(사람이 정한다).

1. **숫자 대조:** 슬라이드의 숫자가 근거 자료와 맞는가. 맞지 않으면 슬라이드 번호·지금 문구·근거 숫자·고칠 문구.
2. **주장의 강도:** 실험 1~2회나 정답 영상 1개로 낸 결론을 단정적으로 말한 곳. "설계안·미측정"이 표시돼야 하는데 빠진 곳.
3. **흐름:** 처음 보는 사람(교수님·다른 팀)이 "문제 → 시도 → 발견 → 해결 → 남은 문제"를 따라올 수 있는가. 빠진 설명, 너무 어려운 용어(fps, RPM, 토큰 등).
4. **예상 질문과 답:** 나올 만한 질문 10개와 근거 자료 기준 답. 특히 아래 "알려진 약점".
5. **시간:** 발표 메모 기준 몇 분인가. 10분 안에 들어가는가(발표 시간은 사람이 확인).

## 먼저 볼 알려진 약점 (검토 세션이 판단해 달라)

| 슬라이드 | 지금 문구 | 문제 |
| --- | --- | --- |
| 표지·정리 | "12분에서 30초로", "첫 결과까지 30초" | 30~35초는 **실험 스크립트**(두 모델 섞기, 3.1이 섞여 평가가 약함) 결과다. **앱(로컬 서버) 실측은 첫 장소 91초, 전체 223초**(보고 4절). 어느 숫자를 내세울지, 둘 다 보여 줄지 |
| 한도 맞추기 | "0초 → 30초 → 60·120초 보강 → 150초" 흐름 | 설계안이고 보강 단계는 측정하지 않았다(슬라이드에 "설계안, 미측정" 표시는 있음). 앱 실측 223초와 함께 보면 오해 소지 |

| `stack` 슬라이드 | (다른 세션이 추가) | 나머지 슬라이드와 숫자·용어가 맞는지 |

## 지켜야 할 사실 (바꾸면 안 되는 것)

- Gemini는 관찰만, Bedrock은 해석만, 확정·집계·순위는 규칙 코드(CLAUDE.md).
- 영상은 내려받지 않는다. 같은 YouTube 주소에 시작·끝 시각만 지정한다.
- 무료 한도는 모델마다 따로이고, 같은 키 안에서 여러 모델을 쓰는 것은 공식 한도 안이다(계정을 늘려 피하는 것이 아님).
- Bedrock은 학교 LLM 게이트웨이로 부른다(결정 0007).
