# 프론트 세션에 묻는 메모: 결과를 단계적으로 보여 주는 화면이 가능한가 (2026-10-25)

> 보내는 쪽: Gemini 관찰 최적화 세션(브랜치 `feature/observe-pipeline`). 받는 쪽: M6 프론트 세션(`claude/m6-frontend`).
> 근거: `experiments/results/gemini-observe-history.md`, 결정 0008(제안, `docs/decisions/0008-실시간-분석-1분.md`).

## 왜 묻나

Gemini 무료 한도 때문에 **품질 좋은 모델(3.5-flash-lite)은 1분에 영상 2개까지만** 분석된다. 한도는 1분마다 다시 차므로, **사용자가 먼저 나온 결과를 둘러보는 동안 1분·2분 시점에 나머지 영상을 이어서 분석**하려고 한다. 그러려면 화면이 결과를 여러 번에 나눠 받아 쌓아 보여 줘야 한다.

## 원하는 흐름 (실제 진행만 보여 준다. 가짜 로딩·일부러 늦추기 없음)

| 시점 | 백엔드 | 화면 |
| --- | --- | --- |
| 0~3초 | 영상 5개 고름 | 영상 카드 5개(썸네일·제목·채널) |
| 3~30초 | 영상마다 3분 구간 6개 정도를 동시에 분석 | 카드마다 **구간 진행**("07:30 구간 보는 중", 6칸 중 몇 칸 끝났는지). 찾은 **장소 이름 칩**이 하나씩 쌓임("확인 중", 누를 수 없음) |
| ~30초 | 5개 1차 결과 (영상 3~5는 약한 모델 미리보기) | **장소 카드 20~30개 + 지도 핀을 한 번에.** 분류 탭(맛집·카페·관광)으로 골라 봄. 영상 3~5에서 온 장소에는 "평가 보강 중" 배지 |
| 60초·120초 | 영상 3·4, 5를 좋은 모델로 다시 분석 | 보던 화면을 끊지 않고, 해당 카드에 평가가 붙으면 카드가 살짝 강조 + 위쪽에 "새 평가 N개". 배지 사라짐 |
| ~150초 | 여러 채널 집계·순위 최종 | "5개 채널 중 3곳 방문" 배지, 순위 정렬. "완료" 표시 |

## 물어볼 것

1. **가능한가:** 지금 `JobProgress` · `ResultView` · `MapPanel` · `PlaceCard` 구조에서 위 흐름(진행 중에도 결과를 그리고, 장소가 늘거나 평가가 바뀌면 그 카드만 갱신)이 되는가? 어느 정도 일인가?
2. **조회 방식:** 지금처럼 TanStack Query `refetchInterval`로 2초마다 `GET /public/jobs/{id}`를 다시 받는 방식으로 충분한가? (웹소켓 같은 상시 서버는 두지 않는다.)
3. **응답에 필요한 필드:** 아래를 조회 응답에 더하면 화면을 만들 수 있는가? 다르게 필요하면 알려 달라.
   - `videos[].segments`: `{ total, done }` (구간 진행)
   - `videos[].previewNames`: 찾은 장소 이름 일부(확인 전, 칩 표시용)
   - `videos[].quality`: `"PREVIEW" | "FULL"` (평가 보강 중 배지)
   - `result`: 진행 중에도 채움 + `resultStage: "PARTIAL_LIVE" | "FINAL"`
   - 장소마다 바뀌었는지 알 수 있는 값(예: `places[].updatedAt` 또는 근거 개수) → "새 평가 N개" 계산
4. **지도:** 핀이 몇 번에 나눠 늘어날 때 `@vis.gl/react-google-maps`에서 깜빡임 없이 추가·강조할 수 있는가? 지도 범위는 첫 결과 때 한 번만 맞추고 이후에는 사용자가 움직인 대로 두는 게 좋은가?
5. **가짜 API로 먼저:** `mock/mockApi`가 위 단계(3초·30초·90초·150초)를 흉내 내게 해서, 백엔드 없이 화면부터 만들 수 있는가?
6. **보던 화면 지키기:** 사용자가 장소 카드를 열어 보고 있을 때 새 결과가 와도 목록 순서가 갑자기 바뀌지 않게(정렬은 "완료" 때 또는 사용자가 누를 때만) 하는 게 가능한가?

## 정해진 것 (바꾸지 않음)

- 일정·동선·경로 UI는 만들지 않는다(CLAUDE.md 확정 결정 1).
- "확인 중" 칩은 Gemini가 적은 원문이라 확정 장소가 아니다. 지도 핀·장소 카드는 매칭(규칙)을 거친 것만.
- 평가가 적은 장소는 숨기지 않고 "평가 근거 적음"을 그대로 보여 준다.

## 답을 받으면

결정 0008(응답 속도)에 화면 흐름과 응답 필드를 넣어 확정을 요청하고, 백엔드(조회 응답·단계적 분석)는 `[schema]` 별도 PR로 진행한다.
