# 0003. M2 규칙 구현 중 드러난 명세 빈틈 (2026-10-15)

상태: **제안 — 확인 필요** (코드는 아래 기본안으로 구현돼 있고, 바꾸면 해당 테스트와 함께 고친다)

## 1. 평가는 방문(VISITED) 근거만 센다

- 문제: §5.5 "평가: 항목별로 채널 단위 집계"가 단순 언급(MENTIONED) 근거의 평가를 셀지 정하지 않았다.
- 기본안: VISITED 근거의 평가만 센다. "거기 비싸다던데" 같은 전해 들은 평가는 세지 않는다.
- 코드: `rules/aggregation.py` `aggregate_places`

## 2. 시간 근거도 종류에 따라 방문 근거만 쓴다

- 문제: 언급만 한 영상의 시간 근거를 쓸지 정해지지 않았다.
- 기본안: 장면(SCENE)·방문 시각(STATED_TIME)·대기 경험(WAIT_EXPERIENCE)은 방문해야 성립하므로 VISITED 근거만 쓴다. 제작자 추천(CREATOR_TIP, "여긴 꼭 오픈 직후에 가세요")은 방문 영상이 아니어도 쓴다.
- 코드: `rules/time_evidence.py` `_NEEDS_VISIT`

## 3. 대기 경험의 "같은 방향"은 그 근거의 wait 평가로 판단한다

- 문제: §5.5 "같은 방향 WAIT_EXPERIENCE가 2채널 이상일 때 추천"인데, 시간 근거에는 방향(대기 짧음/김) 필드가 없다.
- 기본안: 같은 근거 아이템의 `ratings.wait`로 판단한다. 같은 상황(예: OPENING)에서 대기가 짧았다(wait POSITIVE)는 채널이 2곳 이상이면 `recommend=true`. 대기가 길었다는 채널이 많아도 추천으로 만들지 않고 나열만 한다("점심 대기 김(2곳)").
- 코드: `rules/time_evidence.py` `_recommend`

## 4. 대체 영상으로 메워진 실패는 PARTIAL이 아니다

- 문제: 결정 0002-5(실패 영상 대체)를 넣으면서, 실패했지만 대체가 성공한 경우의 작업 상태가 정해지지 않았다.
- 기본안: 대체가 성공하면 SUCCEEDED. 대체가 없거나 대체도 실패하면 PARTIAL. 결과의 `failedVideos`는 실패 영상 수를 그대로 센다.
- 코드: `rules/aggregation.py` `job_status`

## 5. 선호 스타일 일치 판단

- 문제: §5.5 "선호 스타일 일치에 가중치"인데, 스타일과 장소를 어떻게 맞출지 정해지지 않았다.
- 기본안: 맛집 → RESTAURANT, 카페·포토스팟 → CAFE, 관광·역사 → ATTRACTION, 가성비 → 가격 긍정 채널이 1곳 이상, 쇼핑 → 대응 분류가 없어 가중치 없음.
- 코드: `rules/ranking.py` `STYLE_CATEGORIES`, `style_match`

## 6. 언급만 된 장소는 순위·지도에서 뺀다

- 문제: 지점 매칭은 확정됐지만 방문 채널이 0인 장소(언급만 됨)의 처리가 정해지지 않았다.
- 기본안: 순위에서 뺀다(지도 핀 없음). 서비스 핵심이 "여러 채널에서 확인된 방문"이기 때문.
- 코드: `rules/ranking.py` `rank_places`

## 참고 (답 필요 없음)

- 숫자 값은 M7 실험에서 dev 라벨로 조정한다: 이름 유사도 임계값 0.8, 명시적 긍정 가중 0.5, 스타일 가중 1.0, 참고 채널 가중 1.0. 코드에 `TODO(tune)`으로 표시.
- 지점 단서는 `branch_hint`의 단어가 모두 결과 이름·주소에 들어 있어야 맞는 것으로 본다(결정 0002-4). 예: "도톤보리 별관" → 이름·주소에 "도톤보리"와 "별관"이 모두 있어야 함.
- 동점은 방문 채널 수 → placeId 순으로 정해 항상 같은 순서가 나오게 했다.
- 지역 묶음(`areaGroup`)은 집계 핸들러와 함께 M4에서 만든다.
