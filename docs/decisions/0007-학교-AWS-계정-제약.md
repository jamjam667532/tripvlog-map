# 0007. 학교 AWS 계정 제약에 맞춘 구조 변경 (2026-10-25)

상태: **확정** (2026-10-25, 1~6 기본안대로. 5번 배포는 콘솔 직접)

근거: 2026-10-25 학교 계정 발급 회신(NxtCloud 김수민). 계정 정보와 "LLM API KEY"는 개인 DM.

## 회신 요약

| 구분 | 내용 |
| --- | --- |
| 허용 | Lambda, ECR, Step Functions, API Gateway, DynamoDB, S3, CloudFront(WAF 끔), EventBridge Scheduler, CloudWatch. Bedrock은 US 리전 전부 |
| 불허 | **Cognito**, **SSM Parameter Store** |
| 리전 | **ap-northeast-2(서울) 고정**, Bedrock만 US |
| 이름 | 접두사 **`sgu-clicktotrip`** 필수(S3·DynamoDB·상태 머신은 아니면 생성 거부) |
| 역할 | 새로 못 만듦. Lambda·Step Functions·Scheduler 모두 **`SafeRole-sgu-clicktotrip`** |
| 자격증명 | **Access Key 발급 불가.** 공용 계정이라 **Lambda 환경 변수에 비밀값 금지** |

목록에 **CloudFormation·IAM이 없다.** CDK는 CloudFormation으로 배포하고, bootstrap과 기본 구성이 IAM 역할을 만든다.

## 결정 (기본안)

### 1. 리전은 서울, Bedrock은 학교 LLM 게이트웨이(OpenAI 호환)로 호출 (2026-10-25 갱신)

- Lambda·DynamoDB·S3·Step Functions·API Gateway·CloudFront는 ap-northeast-2.
- Bedrock은 boto3로 직접 부르지 않고, 학교가 준 **OpenAI 호환 게이트웨이**(`base_url` + `sk-` 키, 키·주소 한 쌍)로 부른다. 키와 주소로 호출되는 것은 팀이 확인했다. Bedrock 리전은 게이트웨이가 정하므로 우리 설정에서 리전은 빠진다.
- 모델은 별칭으로만 부른다(원본 ID는 거부):

  | 별칭 | 실제 모델 | 우리 용도 |
  | --- | --- | --- |
  | `bedrock-haiku` | Claude Haiku 4.5 | 해석(interpret) 기본 |
  | `bedrock-gpt-5.6-luna` | GPT-5.6 Luna | 규칙 vs Bedrock 비교 실험(M7) |
  | `bedrock-sonnet` | Claude 3.5 Sonnet v2 | 쓰지 않음(필요하면 M7 비교에만) |

  Nova Micro는 목록에 없다 → 스타일 태깅은 규칙 키워드만 쓴다(`STYLE_TAGGING_ENABLED=false` 유지).
- 클라이언트: `shared/clients/bedrock.py`에 `GatewayChatInterpreter`(chat.completions)를 추가하고, `BedrockInterpreter` Protocol은 그대로 둔다. 핸들러·규칙·스키마는 바뀌지 않는다. 토큰은 `usage.prompt_tokens`/`completion_tokens`.
- 키·주소는 3번의 설정 버킷 `keys.json`(`llm_api_key`, `llm_base_url`)에 둔다. 게이트웨이 안내문은 환경 변수를 권하지만, AWS 계정 규칙(Lambda 환경 변수에 비밀값 금지)이 우선이다. 로컬 실험은 `.env`(이미 gitignore)에서 읽는다.
- 오류 처리:
  - `Budget has been exceeded`: 키 단위 한도에 걸렸다는 뜻. 재시도하지 않고 바로 실패(`ExternalApiError`, 코드 `BUDGET_EXCEEDED`). 대체 영상도 쓰지 않는다.
  - 429: 지수 백오프로 최대 3회. 형식 검증 재요청(1회)과 따로 센다.
  - 401, `key not allowed to access model`, `model not found`: 설정 오류이므로 재시도하지 않는다.
- 게이트웨이는 요청 내용을 일정 기간 로그에 보관한다. 우리가 보내는 것은 공개 영상의 관찰 단서뿐이다(개인정보·Places 응답·좌표 없음). 이 원칙을 계속 지킨다.
- CLAUDE.md 확정 결정 4를 "Bedrock은 학교 LLM 게이트웨이로 호출, 나머지는 ap-northeast-2"로 고친다. 모델 ID는 하드코딩하지 않는다는 원칙은 별칭에도 적용한다(`BEDROCK_INTERPRETER_MODEL_ID=bedrock-haiku`).

### 2. 로그인: 1단계는 게스트만, 2단계(M8)는 Google ID 토큰을 HTTP API JWT Authorizer로 직접 검증

- 1단계(M5~M7)는 지금 설계대로 `/public/*` 게스트 모드만. 영향 없음.
- M8: 브라우저가 Google Identity Services로 **ID 토큰**을 받고, API Gateway HTTP API의 JWT Authorizer가 바로 검증한다.
  - issuer `https://accounts.google.com`, audience = 우리 OAuth 클라이언트 ID. Cognito 없이 "경로별 인증", "userId는 JWT `sub`" 원칙이 그대로 유지된다.
  - Users 테이블 키는 Google `sub`(`google:` 접두사).
  - ID 토큰 수명이 1시간이라 브라우저가 GIS로 조용히 다시 받는다. 서버는 토큰을 저장하지 않는다(확정 결정 3 유지).
  - JWT를 직접 만들고 서명하는 방식은 키 관리·폐기를 우리가 떠안으므로 쓰지 않는다.
- TODO(verify): Google ID 토큰의 `iss`가 `accounts.google.com`(스킴 없음)으로 오는 경우가 있다. HTTP API Authorizer는 issuer를 정확히 비교하므로 M8에서 실제 토큰으로 확인한다.
- CLAUDE.md 확정 결정 2의 "Cognito JWT"를 "Google ID 토큰 JWT"로 고친다.

### 3. 서버 키: SSM 대신 설정 버킷 `sgu-clicktotrip-config/keys.json`

- `shared/clients/secrets.py`만 바꾼다. 콜드 스타트에 S3 객체를 1회 읽어 프로세스 메모리에 캐시하고, `get_secret(name)`은 JSON의 키를 돌려준다(`gemini`, `youtube`, `places`).
- 환경 변수에는 버킷·객체 키 이름만 넣는다(`CONFIG_BUCKET`, `CONFIG_KEY`). 값은 넣지 않는다.
- 버킷은 웹 버킷·결과 버킷과 분리하고, 퍼블릭 액세스 차단 + SSE-S3 + 버킷 정책으로 SafeRole만 `GetObject`.
- 테스트는 moto S3로 바꾼다. 로그에 값·JSON을 남기지 않는 원칙은 그대로다.
- **남는 위험:** 같은 계정의 콘솔 사용자는 버킷을 볼 수 있다. 관리자 권고안이라 받아들이고, 키는 API·도메인 제한(YouTube·Places는 API 제한, Gemini는 프로젝트 전용 키)으로 피해를 줄인다.

### 5. 배포: CDK를 접고 "zip 빌드는 CI, 생성·업로드는 사람(콘솔)"

- CloudFormation·IAM이 목록에 없고 Access Key도 없어서 `cdk deploy`·GitHub Actions OIDC 배포 모두 안 된다고 본다.
- **Lambda는 컨테이너 이미지 대신 zip**으로 바꾼다. 컨테이너는 ECR에 `docker push`할 자격증명이 필요하지만 zip은 콘솔에서 올릴 수 있다.
  - 함수 하나당 zip 하나 대신 **공통 zip 하나 + 핸들러 경로만 다르게**(`functions.observe.handler.handler`). 의존성(pydantic, google-genai)은 같은 zip에 넣는다. 압축 50MB·압축 해제 250MB 안에 들어간다(TODO(verify): 실제 크기).
  - CI(`ci.yml`)가 `pip install --platform manylinux2014_x86_64 --only-binary=:all:`로 zip을 만들어 artifact로 올린다. 사람이 내려받아 콘솔에서 올린다.
- Step Functions ASL은 `infra/asl/analyze.asl.json`으로 저장소에 두고 콘솔에 붙여 넣는다. 지금 `tests/integration/pipeline.py`와 같은 순서·이벤트를 쓴다.
- 콘솔 작업 순서는 `docs/deploy-runbook.md`(신규)에 체크리스트로 적는다. 두 사람이 같은 리소스를 쓰므로 배포는 한 사람만, 버전 태그를 runbook에 기록한다.
- `infra/`의 CDK 앱은 지운다. `infra/config.py`는 값 목록(환경 변수 표)으로 남긴다.
- CLAUDE.md 기술 스택·명령(`cdk synth`)과 spec §CI·M5를 고친다.

### 6. 권한·공개 API 보호

- 모든 함수가 SafeRole 하나를 쓰므로 함수별 최소 권한은 못 한다. 대신 코드에서 함수가 쓰는 테이블만 `Repos`에 넘기는 지금 구조를 유지한다.
- CloudFront WAF를 못 쓰므로 `/public/*` 보호는 **HTTP API 스테이지 스로틀(rate·burst)** + 지금 있는 DynamoDB 일일 예산 카운터(YouTube 검색, 결정 0006-5의 Gemini 요청)로 한다.
- 환경 변수에 비밀값 금지 원칙을 CLAUDE.md 코딩 규칙에 추가한다.

## 대안 (채택하지 않음)

- **Bedrock까지 서울 리전:** 서울에서 쓸 수 있는 모델이 적고, 회신이 "Bedrock은 US"라고 정했다.
- **JWT 직접 발급(자체 로그인):** 키 보관·폐기·재발급을 직접 만들어야 하고, 키를 둘 곳이 결국 설정 버킷이다.
- **컨테이너 이미지 유지:** ECR 푸시 경로가 없다. CloudShell에서 docker가 되면 다시 볼 수 있다.
- **비밀값을 Lambda 환경 변수로(KMS 암호화):** 관리자가 명시적으로 금지했다.
